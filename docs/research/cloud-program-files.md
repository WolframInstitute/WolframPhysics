# Cloud program files sweep: Wolfram Language program files loaded by the Physics Project technical introduction, the bulletins, the writings and Community posts

Research report for the WolframInstitute/WolframPhysics paclet guide page. Source swept: the Wolfram Language program files (.wl and other cloud objects) that the technical introduction, the four Physics Project bulletins, Stephen Wolfram's writings (2020 to 2026) and Wolfram Community posts load with CloudGet, Get, the << operator or Import from the Wolfram Cloud. Sweep date: 2026-09-17. Kernel: WL 15.0 via wolframscript, cloud-connected.

Status column: "seen" means the definition was seen by me in the fetched file text and, unless noted, was loaded into a WL 15 kernel (Get into a fresh context) where it produced DownValues, SubValues, UpValues or OwnValues; "unconfirmed" means the name only appears inside a comment of the file (a Preparation Code cell) or could not be loaded; "seen (head only)" means the symbol is used as an expression head without any definition. No file in this sweep carries usage messages (the two usage strings in YoungTableauToPoset.wl are commented out), so every Description is a paraphrase of the definition, marked "paraphrase", preceded by the call signature taken from the loaded DownValues. Names with a dollar-sign prefix are written in code spans. The Used by column counts the inputs (click-to-copy code files or pre blocks) of each corpus that mention the name; TechIntro means the technical introduction, post codes are those of the writings report legend (Path2020, FTL2020, Euclid2020, Metamath2022, MTM2021 and so on), and Community entries are Wolfram Community topic numbers. A name defined in several files gets the same counts in each file.

## Method

Every step below was actually run; scratch files live under the session scratchpad directory cpf/.

1. Technical introduction crawl (ti_crawl.py). Fetched https://www.wolframphysics.org/technical-introduction/ with curl, collected every href beginning with /technical-introduction/ (the sidebar), fetched each page, collected hrefs again transitively, and downloaded every file named in a data-c2c-file attribute: 128 page URLs (97 with code, 31 without: section landing pages, the root, css and pdf links, appendix pages) and 1309 click-to-copy code files, saved as ti/pages/<slug>/ and ti_pages.json. The 1309 files contain 134 CloudGet inputs and 9 Import inputs of .wxf data objects.
2. Load targets in the technical introduction: every wolfr.am short link in the 1309 files (42 distinct) was resolved with curl -sI (Location header) into 42 TechPaper-Programs files (short_ti_resolved.tsv). The code also names four of them by full URL and six wolframphysics/Data .wxf objects (listed in the Other load targets table).
3. Writings posts. The 88 post HTML pages and their 6045 click-to-copy files (data-c2c-file and data-src attributes on content.wolfram.com, both quote styles) downloaded earlier in this session by the writings sweep (scratchpad sw/posts and sw/c2c) were reused; two referenced files are missing there (one 404, one malformed URL in V13.1 and V14.3, not physics posts). I re-fetched the year archives https://writings.stephenwolfram.com/2022/ to /2026/ with their page/2 continuations (curl, 7 pages) and confirmed all 59 posts of 2022 to 2026 are in that download. Each post's code (pre class text blocks plus the txt files, HTML-unescaped, box-form strings joined) was searched for CloudGet, Get, Import, CloudImport, the << operator, wolfr.am links and wolframcloud.com/obj URLs (post_targets.json). The 53 short links were resolved with curl -sI (short_resolved.tsv).
4. Bulletins. The four bulletin pages fetched from the Wayback Machine by the writings sweep (https://web.archive.org/web/2024id_/https://bulletins.wolframphysics.org/2020/06/exploring-rulial-space-the-case-of-turing-machines/, .../2021/02/multiway-turing-machines/, .../2021/10/multicomputation-with-numbers-the-case-of-simple-multiway-systems/, .../2020/05/event-horizons-singularities-and-other-exotic-spacetime-phenomena/) and their 647 content.wolfram.com code files (scratchpad sw/bull and sw/bullc2c) were reused and searched the same way: MTM2021 loads sw-blog/MultiwayTuringMachines/Programs-01.wl in 124 inputs; RulialTM2020 loads wolframphysics/Bulletin/DeltaTM.wl (69), TMCausal.wl (6), SortingNetworks.wl (1) and wolfr.am/N9FGlZe8 (1); MultiNum2021 and EventHorizons2020 load no cloud file.
5. Community. The files named in docs/research/wolfram-community.md (two TechPaper Section-05 files, the sw-blog files, https://www.wolframcloud.com/obj/ccn2/freeform/petrinet/monoid/init and .../rewriting/text/peano/init) were added; the community sweep's mined.json (needs and used fields of 731 topics) gave the Community columns; wolfr.am/1z88Lc63z and wolfr.am/1z88b1Snz (post t/26058) were resolved with curl -sI to the peano and petrinet init objects respectively.
6. Downloads. Every target was fetched with curl -L -A Mozilla (dl.sh, dl1.tsv, dl_tp.tsv). Eight objects came back as the cloud HTML viewer page (title "Wolfram Cloud Page"): Section03/PossibleRules-01.wl, Blogs/FourthParadigm/HelperFunctions, BlogHelpers, Bulletin/DeltaTM.wl, TMCausal.wl, SortingNetworks.wl and the two ccn2 init objects. Import[url, "Text"] in the kernel (kfetch.wls) also returned the viewer HTML; Import[CloudObject[url], "Text"] together with CloudObjectInformation (kfetch2.wls) returned the sources of all eight (owners wolframphysics@wolfram.com and dara@lossofgenerality.com). No object required a sign-in, so nothing is private. The copy-input objects and the two UUID objects of the CanAI2024 post were classified with CloudObjectInformation and Import[CloudObject[url], "Text"] (kfetch3.wls, kfetch4.wls): they are data expressions, not program files. CloudObjects on the folders (listdirs.wls) listed only TechPaper-Programs (seven sub-folders), Section03, sw-blog/Combinators (Programs.wl, Data, CombinatorEvolve-0.0.5.paclet) and sw-blog/PostTagSystem (Programs-01.wl, Data, PostTagSystem-0.0.34.paclet); every other folder returned Failed.
7. Large files. sw-blog/EuclidBlog/Programs/Programs-02.wl, -05.wl and -06.wl (5.3 MB, 12.3 MB and 24.3 MB by CloudObjectInformation, sizes.wls) were cut off by the cloud after about five minutes in every attempt (curl with and without a time limit, curl -C resume, CopyFile of the CloudObject in the kernel, kfetch5.wls); the largest partial copies (4.17 MB, 4.11 MB and 2.4 MB) were catalogued from their text and the files are marked in the Gaps section.
8. Catalogue (catalog3.wls for the TechPaper files, catalog4.wls for the rest). For each file, in one kernel per file: Get of the local copy inside Quiet and TimeConstrained 120 with the variable Context (dollar prefix) set to a fresh Sweep context and ContextPath to System only; catalog4.wls additionally stubs ResourceData and PacletInstall (they blocked on the slow cloud). Then for every name of the Sweep context: the number of DownValues, OwnValues, SubValues and UpValues, Attributes, Options, the usage message if any, and the first DownValue left-hand side as the signature (catalog_merged.json). datafiles.wls evaluated the data-only files and recorded the head, length and byte count of the value they return.
9. Text-level definitions (textheads.py): every head defined at line start with := or = or ::usage or /:, Options and SetAttributes assignments and section cell titles, to catch definitions that fail to load or live in comments (textheads.json); defs.py printed each definition block with the ResourceFunction calls it contains, which is the basis of the paraphrases and of the "calls ResourceFunction" flags.
10. Usage counts (usage2.py): one alternation regex of all defined names, applied to each technical-introduction code file, to each post and bulletin input (inputs_posts_bulletins.json) and to the community mined data; loads.json records, per file URL or short link, the inputs that mention it.
11. Repository check (rocheck.wls): ResourceObject[name] inside Quiet and TimeConstrained 90 for all 327 capitalized names, recording the ResourceType, Name and Description when a resource exists, plus Names of the System context for each name (rocheck.out): 26 names are also Wolfram Function Repository functions (flagged in the Topics column), 12 names hit System symbols and were dropped as false positives of the text scan.
12. Verification (headcheck.sh): every file URL re-fetched with curl -L on 2026-09-17 (headcheck.tsv), and every table name grepped in the file text it is attributed to.

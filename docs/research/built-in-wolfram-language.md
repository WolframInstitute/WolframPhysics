# Built-in Wolfram Language functions relevant to the Wolfram Physics Project

Survey of the System context of Wolfram Language 15.0 (kernel: 15.0.0 for Mac OS X ARM (64-bit), May 19, 2026) for the functions the Wolfram Physics Project relies on: rewriting and computational systems, graphs for states, causal and branchial structure, hypergraph adjacent structures, geometry and dimension estimation, relativity, quantum, group theory, trees and expression structure. Every function in the Findings tables was confirmed to exist in the kernel by evaluation, and the URL column records the guide page on which it was also seen when there was one. There is no built-in Hypergraph, WolframModel, MultiwaySystem, CausalGraph or BranchialGraph symbol; those live in the Function Repository and in paclets covered by other finders.

## Method

### Kernel evaluations (wolframscript -file, WL 15.0)

All scratch files live in the session scratchpad directory (/private/tmp/claude-501/-Users-swish-src-wolfram-WolframPhysics/afd62ccd-b6b1-4cdd-ab6e-411aab4a1e8a/scratchpad/).

1. test1.wls: printed VersionNumber and Version, then `` Names["System`Graph"] ``, `` Names["System`TaggedNestGraph"] ``, and Names with the System context patterns Combinator*, *Multiway*, *Hypergraph*, *Causal*, *Lorentz*, *Minkowski*, *Quantum*, *Rewrit*, *Wolfram*; printed Graph::usage and SubstitutionSystem::usage in InputForm; tested `WolframLanguageData[{"Graph", "SubstitutionSystem"}, "PlaintextUsage"]`.
2. discover.wls: ran `` Names["System`" <> pattern] `` for 145 wildcard patterns (among them *Graph*, Tree*, *Tree*, Combinator*, *Group*, *Permutation*, Sequence*, Nest*, *Replace*, *Isomorph*, *Multi*, *Hyper*, *Mesh*, *Dimension*, *Curvature*, *Relativ*, Cellular*, Turing*, Substitution*, *Automat*, *Component*, *Vertex*, *Edge*, Find*, *Canonical*, Boolean*, *Pattern*, Rule*, *Cycle*, *Ordering*, *Tag*, *Lambda*, *Combinat*, *Multiway*, *Ruli*, *Fold*, *Fixed*, *Centrality*, *Distance*, *Topolog*, *Transitive*, *Layered*, *Lattice*, *Torus*, *Cube*, *Grid*, *Geodesic*, *Manifold*, *Metric*, *Causal*, *Branch*, *Rewrit*, *Match*, *Cases*, *Position*, *Subset*, *Tuple*, *Partition*, *Orbit*, *Stabilizer*, *Cayley*, *Coxeter*, *Knot*, *Braid*, *Homology*, *Simplicial*, *Poset*, *Dispatch*, *Verbatim*, *Category*, *Functor*, *Morphism*, *Monoid*, *Tensor*, *Spin*, *Entangle*, *Qubit*, *Unitary*, *Hermitian*, *Wigner*, *Bra*, *Ket*, *Hilbert*, *Path*, *Flow*, *Cut*, *Clique*, *Communit*, *Highlight*, *Embedding*, *Adjacency*, *Incidence*, *Kirchhoff*, *Laplacian*, *Transient*, *Repeat*, *Entropy*, *Hash*, *Expression*). Output saved to discover.out (35 KB). Empty results: *Multiway*, *Ruli*, *Manifold*, *Metric*, *Causal*, *Rewrit*, *Coxeter*, *Braid*, *Homology*, *Simplicial*, *Poset*, *Functor*, *Morphism*, *Monoid*, *Spin*, *Entangle*, *Qubit*, *Attractor*. *Hypergraph* matched nothing; *Hyper* matched only HypercubeGraph, Hyperplane and hypergeometric functions. *Lorentz* matched nothing and *Minkowski* matched only MinkowskiQuestionMark. *Quantum* matched nothing.
3. verify.wls: for 621 candidate names grouped by topic, evaluated `` Names["System`" <> name] === {name} ``; 580 distinct names present, 41 absent (listed under Gaps). For every present name it fetched the first line of `WolframLanguageData[name, "PlaintextUsage"]` (falling back to the name::usage message with box structures flattened) and wrote verify.tsv. It also evaluated `TaggedNestGraph[{#+1, 2 #}&, 1, 2]` (edges tagged 1 and 2) and printed the raw usage messages of the new WL 15 symbols.
4. probe2.wls: printed name::usage, Attributes and documentation notebook presence for TaggedNestGraph, TaggedEdgeStyle, GraphRoot, GraphLayerLabels, LambdaComponents, BooleanGraph, GraphTree, GraphHub, LayeredGraph, GraphLayers, KirchhoffGraph, RandomTree, DominatorTreeGraph, SubsetReplace, GraphLayerStyle, LayeredGraph3D. Four symbols (TaggedNestGraph, TaggedEdgeStyle, GraphRoot, GraphLayerLabels) have no usage message. The local Documentation directory contains no reference notebooks (FileNames returned 0), so documentation presence was checked on the web instead.
5. verify2.wls: verified 106 further names collected from the guide pages (all present), wrote verify2.tsv, and ran two multiway examples: `NestGraph[Function[s, Union[ReplaceList[s, {x___, 0, 1, y___} :> {x, 1, 0, y}]]], {{0, 0, 1, 1}}, 4]` gave the six-edge states graph of the sorting system, and `TaggedNestGraph[Function[s, ReplaceList[s, {{x___, 0, 1, y___} :> {x, 1, 0, y}, {x___, 1, 1, y___} :> {x, 0, y}}]], {{0, 1, 1}}, 3]` gave edges tagged {1, 2, 1, 1}, showing that the tag is the position of the successor in the list returned by f (not the rule index). `LambdaComponents[CompleteGraph[4]]` returned {{1}, {2}, {3}, {4}, {1, 2, 3, 4}} (a graph connectivity function, not lambda calculus).

### Reading the tables

Source WL means a System context symbol confirmed by `` Names["System`Name"] `` in verify.wls or verify2.wls, so every WL row has Status seen. The URL is the guide page where the symbol was also seen, or a fetched ref page, or otherwise the ref page URL formed as https://reference.wolfram.com/language/ref/Name.html (not individually fetched). Descriptions are the first line of the symbol's usage message as returned by WolframLanguageData "PlaintextUsage" or the kernel usage message, with ellipses kept and vertical bars escaped. A symbol that belongs to several topics appears once, in the first topic, with all its topics in the Topics column.

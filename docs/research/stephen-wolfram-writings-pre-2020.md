# Stephen Wolfram Writings sweep, 2015 to 2019: Wolfram Language functions that seed the Wolfram Physics Project

Research report for the WolframInstitute/WolframPhysics paclet guide page. Source swept: the 2015 to 2019 posts on writings.stephenwolfram.com (the companion report stephen-wolfram-writings.md covers 2020 to 2026). Sweep date: 2026-09-17. Kernel: WL 15.0 (15.0.0 for Mac OS X ARM, May 2026) via wolframscript, cloud-connected.

Status column: "seen" means the name was seen in a fetched page or file and its existence was confirmed on a public page (reference.wolfram.com usage message via the kernel, Function Repository or Data Repository resource object via the kernel, or a paclet installed in the kernel); "seen (kernel)" means the name was not written in the post but is the documented symbol behind something the post uses, and it was confirmed in the kernel; "unconfirmed" means a post-local definition, pseudo-code or session-only name with no public page or kernel definition.

Summary of what the years contain. The 2015 to 2019 posts carry very little physics-project code: the 2015 spacetime post and the 2017 NKS 15-year view are prose with images only. The code that exists is (a) cellular automaton and iterated-map ruliology (the 2017 experimental mathematics post, the 2019 Rule 30 prizes post, the Feigenbaum obituary, "A World Run with Code"), (b) the equational theorem proving and axiom system functions introduced in Version 11.3 and 12.0 (FindEquationalProof, AxiomaticTheory, Groupings) as used in the Logic and Explainability post, (c) the symbolic geometry functions of Version 12 (GeometricScene and friends), (d) the resource system tooling of the Function Repository launch, and (e) plain-language lambda calculus and combinator reductions in the Turing post. No ResourceFunction name in these years is physics-related; the Wolfram model, multiway and combinator repository functions all date from December 2019 onward and appear in the 2020 posts covered by the other report.

## Method

Every step below was actually run. Scratch files live under the session scratchpad directory in the subfolder pre2020/ (archives/, posts/, posts2/, text/, code/, extract.py, inventory.py, totext.py, kernel1.wls to kernel6.wls, refetch.sh).

1. Enumerated posts. Downloaded with curl (user agent Mozilla/5.0) the year archives https://writings.stephenwolfram.com/2015/ (2 pages), /2016/ (2 pages), /2017/ (2 pages), /2018/ (1 page), /2019/ (2 pages); page 3 of each year returns 404. Collected every post URL of the form /201Y/MM/slug/ with a regex: 65 posts (11 in 2015, 15 in 2016, 13 in 2017, 8 in 2018, 18 in 2019). The full list is in archives/posts.txt.
2. Category pages. Downloaded https://writings.stephenwolfram.com/category/physics/ (5 pages), /category/new-kind-of-science/ (7 pages), /category/mathematics/ (4 pages) and /category/computational-science/ (4 pages), with /page/N/ pagination until 404. The 2015 to 2019 posts they list (22 URLs) are all already in the year archives; the membership is recorded in archives/cat-membership.txt (physics: What Is Spacetime Really, Black Hole Tech, Alien Spacecraft, NKS 15-Year View, Eclipse, Gell-Mann, Feigenbaum; new-kind-of-science: Two Hours of Experimental Mathematics, NKS 15-Year View, Covered in Rule 30s, On Growth and Form, Beacons, Logic and Explainability, A World Run with Code, Santa Fe Institute, Rule 30 Prizes; mathematics: Pi Day, Boole, Lovelace, Ramanujan, Golomb, Experimental Mathematics, Eclipse, Logic and Explainability, Spikey, Feigenbaum, Rule 30 Prizes; computational-science: What We've Built Is a Computational Language).
3. Downloaded all 65 posts with curl (posts/). Inventoried how code is embedded (inventory.py): in 2015 to mid-2017 posts the code is only in the alt and title attributes of the code images (for example title="RulePlot[CellularAutomaton[90]]"); from the Eclipse post (2017-08) onward the copyable inputs are in pre elements with class text and ids ending in _out_text (single-quoted attributes, so a grep for the double-quoted form finds nothing); no post in these years uses data-c2c-file or data-src click-to-copy .txt files (0 references to content.wolfram.com .txt files across all 65 posts), so there were no code files to download from content.wolfram.com. Total code inputs extracted: 836 (extract.py, results in extracted.json).
4. Extracted from the code (one known artifact: the tag stripper eats the association opener from "<|" up to the first "->" inside pre blocks, so association arguments such as the Feigenbaum 4-color rule and the V12 operator renaming were read from the raw HTML by hand): every ResourceFunction["Name"], every FunctionRepository/resources/ link, every CloudGet, CloudObject, Get, Import and Needs argument, every capitalized head followed by "[" (with per-post counts), and converted each post to plain text (totext.py, text/) to grep the prose for function names (CellularAutomaton, NestGraph, FindEquationalProof, AxiomaticTheory, Groupings, RulePlot, TuringMachine, BooleanMinimize, hypergraph, network substitution, causal and so on).
5. Cloud objects. Fetched with curl the one CloudObject loaded in the Rule 30 post, https://www.wolframcloud.com/obj/bc470188-f629-4497-965d-a10fe057e2fd (1.3 MB HTML cloud page whose embedExpression element holds a list of integer pairs; also evaluated CloudGet on it in the kernel: pure data, no definitions). Probed with curl the wolfr.am short links used by CloudGet in the V11.2, V11.3, V12, Computational Language and Function Repository posts (all resolve to Wolfram Cloud objects holding images or example data, see the cloud table). Fetched https://www.rule30prize.org (linked from the Rule 30 post; it holds no code, only the prize statement, committee and submission form links).
6. Function Repository list. Downloaded https://resources.wolframcloud.com/FunctionRepository/autocomplete/allnames.json (3320 names) and checked every ResourceFunction name and every linked repository page name against it (all 8 present; the session-local example AddOne absent, as expected).
7. Kernel evaluations (wolframscript -file). kernel1.wls: `` Names["System`" <> name] `` and the first line of name::usage (box forms flattened to text) for 122 built-in names used in the posts; all 122 exist in WL 15. kernel2.wls: ResourceObject[name] with properties ResourceType, Description, ContributedBy, ReleaseDate, DocumentationLink and Version for the 8 repository names seen in the posts, for AddOne (returned the failure symbol) and for 21 later repository functions used in the mapping section; ResourceObject on the 5 Data Repository names loaded by ResourceData in the posts; PacletFind for SetReplace (0.3.196 installed), WolframInstitute/Hypergraph (1.2.3) and Wolfram/Multicomputation (0.1.9); CloudGet of the Rule 30 cloud object. kernel3.wls: ContributorInformation and Keywords for the repository names whose ContributedBy was empty, plus `` Needs["SetReplace`"] `` and `` Names["SetReplace`*"] `` (57 symbols, including WolframModel, WolframModelPlot, HypergraphPlot, WolframModelEvolutionObject) and the WolframModel usage message. kernel4.wls: ResourceObject for 10 further repository names used in the mapping section. kernel5.wls: ResourceSearch["randomness test"] (the Function Repository search that the Rule 30 post links to), 9 distinct function names. kernel6.wls: ResourceObject descriptions of those 9 names. All slow calls were wrapped in TimeConstrained.
8. WebFetch verification of five repository pages: https://resources.wolframcloud.com/FunctionRepository/resources/LogoQRCode/, .../StringIntersectingQ/, .../PositionLargest/, .../CreateResourceObjectGallery/ and .../WolframModel/ (names, descriptions and contributors agree with the kernel). A WebFetch of the repository search page https://resources.wolframcloud.com/FunctionRepository/search/?i=randomness+test returned only the site navigation (the results are rendered by JavaScript), so the kernel ResourceSearch was used instead.
9. Re-fetch pass. Downloaded all 65 posts a second time (posts2/, refetch.sh; all 65 returned HTTP 200), re-ran the extractor (extracted2.json) and compared: 0 differences in code inputs, ResourceFunction names or repository links across the 65 posts. Re-fetched the Rule 30 cloud object (identical 1,325,909 character expression).
10. Web searches: none were needed; the year archives and category pages enumerate the source completely. The kagi MCP server was not used (it failed to connect this session).

### 9. The 2015 spacetime post: network substitution and how it maps onto WolframModel and SetReplace

The post contains no evaluated code. Its network material is prose plus six figures hosted on content.wolfram.com/sites/43/2015/11/ and /2015/12/: space-network.png ("Space network", a large trivalent network), graph.png ("A graph"), sample-network-rules.png ("Sample network rules": rules of the form "if you see a piece of network that looks like this, replace it with one that looks like that"), graphs-diff-dimensions.png ("Graphs with different effective dimensions": the ball-volume test, the number of nodes within r connections grows like r to the power d), graphs-ricci-curvatures.png ("Graphs with different effective Ricci curvatures": the correction term to the ball volume proportional to the Ricci scalar), and networks-evolution-rules.png ("Networks from different evolution rules": "the zoo of networks one gets after a fairly small number of steps by using all possible underlying rules of a certain very simple type"). The prose introduces causal networks, causal invariance ("a definite class of underlying rules for which different orderings of underlying updates don't affect that causal network") and the derivation of special and general relativity from them, and points to Chapter 9 of A New Kind of Science (nkschapter9.png) and to notebooks from 2004 (notebooks-from-2004.png). The NKS 15-year view (2017) repeats the same points in prose ("My favorite formulation for a model that's as unstructured as possible is a network: just a collection of nodes with connections between them").

How the 2015 description maps in detail. (1) The 2015 rules act on trivalent (three connections per node) networks as in NKS Chapter 9; WolframModel represents the same idea with hypergraph rules such as {{x, y}, {y, z}} -> {{x, z}, {z, w}, {w, y}}, and a trivalent network is the special case of a hypergraph with binary edges and degree-three vertices. (2) The 2015 "zoo of networks from all possible rules of a very simple type" is EnumerateWolframModelRules followed by WolframModel on each rule. (3) The 2015 update-order problem and the causal network are the "CausalGraph" and multiway properties of WolframModel and MultiwaySystem, with CausalInvariantQ and TotalCausalInvariantQ testing the 2015 "causal invariant" property. (4) The 2015 dimension test (nodes within r connections grow like r to the power d) is HypergraphNeighborhoodVolumes and WolframHausdorffDimension; the Ricci-scalar correction is WolframRicciCurvatureScalar. All of these are documented from the 2020 posts in the companion report.

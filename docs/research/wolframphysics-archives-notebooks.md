# Wolfram Physics Project archive notebooks: functions used in the working material

Source swept: the runnable working-material notebooks listed at https://www.wolframphysics.org/archives/index/ (year index pages 2015 and 2019 to 2026, 1649 notebooks). This report lists every Wolfram Language function, paclet symbol, private cloud resource and recurring helper definition seen in the 1198 notebooks that could be read (1146 downloaded and verified complete against their Content-Length, 52 read only as a truncated prefix because the cloud closes every download after about five minutes; coverage by year, complete or partial: 2015: 1 of 1, 2019: 181 of 221, 2020: 485 of 592, 2021: 151 of 214, 2022: 62 of 103, 2023: 47 of 100, 2024: 114 of 184, 2025: 66 of 107, 2026: 91 of 127). Everything in the tables was seen in a fetched notebook text, a fetched page or a kernel evaluation, and each row says where.

## Method

Everything below was run from a macOS shell on 2026-09-17 with curl, python3 and the WL 15.0 kernel (wolframscript with the -file option on scratch .wls files, cloud-connected). The scratch scripts live under the session scratchpad directory (wpp/mine.py, wpp/aggregate.py, wpp/report.py, wpp/resolve.wls, wpp/resolve_uuid.wls, wpp/pacletsyms.wls, wpp/paclet_usage.py, wpp/doclinks.sh, wpp/verify.py).

### Step 1: collect the notebook list

1. Fetched the nine year index pages with curl: https://www.wolframphysics.org/archives/index?i=2015 and the same URL with i=2019, i=2020, i=2021, i=2022, i=2023, i=2024, i=2025 and i=2026.
2. Extracted every link of the form https://www.wolframcloud.com/obj/wolframphysics/WorkingMaterial/YEAR/Name.nb with a regular expression on the page HTML and de-duplicated. Counts per year: 2015: 1, 2019: 221, 2020: 592, 2021: 214, 2022: 103, 2023: 100, 2024: 184, 2025: 107, 2026: 127, total 1649 (the index pages contain only .nb links; the 1994 to 2004 sub-folders were not visited).

### Step 2: download

1. Rewrote each URL to the download endpoint https://www.wolframcloud.com/download/wolframphysics/WorkingMaterial/YEAR/Name.nb and sent a HEAD request to each (curl with -I and -L, 12 in parallel) to record HTTP status, Content-Length and Content-Type. Result: 1635 return 200 with Content-Type application/vnd.wolfram.nb or application/vnd.wolfram.notebook; 14 return 403 with the JSON body {"errorCode":"not-allowed"} (listed in Gaps).
2. Skipped the 85 notebooks whose Content-Length exceeds 60 MB (listed in Gaps). The remaining 1550 notebooks total 8.5 GB.
3. Downloaded the notebooks with curl (-s, -L) in parallel xargs pools of 12 to 16 workers guarded by a lock directory per file. The cloud serves about 40 to 90 KB/s per connection and about 1 MB/s per client in aggregate, ignores Range requests (also on the /files/UUID and /download/UUID forms of the same object, and through CopyFile of the CloudObject in the kernel, which is no faster), supports gzip transfer but truncates gzip responses of larger notebooks, and closes every plain response after roughly five minutes while still returning HTTP 200. Every downloaded file was therefore compared in size with its HEAD Content-Length; only size-verified files count as complete. Files whose download was cut short were kept as a truncated prefix (the first 3 to 25 MB) in a separate folder and mined as partial text; the report marks them as partial. The over-60 MB notebooks were queued last in the same partial mode.

### Step 3: mine each notebook text (python3, wpp/mine.py)

The notebook file text was decoded as UTF-8 and backslash-newline continuations were joined, then:

1. ResourceFunction names, in the plain form ResourceFunction["Name"], the box form (a token sequence "ResourceFunction", "[", then the boxed string "Name" written as \"Name\" or \"\<Name\>\") and the icon form StyleBox["\<\"Name\"\>", "ResourceFunctionLabel"].
2. Embedded ResourceObject metadata: for every "UUID" -> "..." key the surrounding association (bounded by the nearest ResourceObject[ opening and the next "Name" or "UUID" key) was searched for "Name", "ShortName", "ResourceType", "FunctionLocation" -> CloudObject[...], "DocumentationLink" -> URL[...], "RepositoryLocation" -> URL[...], "ResourceLocations", "SymbolName" and "Description".
3. PacletSymbol["Publisher/Name", "Symbol"], Needs of a context, the << form, Get of a context, PacletInstall targets, and CloudGet, Get, Import and CloudObject URL arguments (plain and box form).
4. Context-qualified names of the form `` Ctx`Name `` (as tokens or inside strings); noise contexts (`` System` ``, `` FunctionRepository` ``, `` OutputSizeLimit` ``, `` Parallel` ``, `` FrontEnd` ``, `` Typeset` `` and the like) were dropped at reporting time.
5. Property strings: the token stream of every box cell was bracket-matched from each call of WolframModel, MultiwaySystem, HGEvolve, Multi, MultiwayTuringMachine, MultiwayCombinator, MultiwayFunctionSystem, MultiwayOperatorSystem, TokenEventGraph, GenerationalMultiwaySystem and a few related heads (bare, wrapped in ResourceFunction["..."] or in the icon form), including chained [...]["Property"] calls; every capitalized string literal inside the call was recorded as a property (or as an option name when followed by -> or :>).
6. Every call head (a name token followed by a "[" token) was counted per notebook, so that bare paclet symbols and bare repository names could be found by comparing against `` Names["System`*"] `` from the kernel (7934 names), the exported symbol lists of the installed paclets, and the Function Repository name list.
7. Top-level definitions: a head token followed by a bracket-matched argument list containing an underscore and then := or =, where the head is the first token of a cell or follows a newline, IndentingNewLine or semicolon token; the first 400 characters of each definition were kept as a snippet. Plain-text (non-box) definitions of the same shape at line start were also counted.

### Step 4: aggregate and resolve

1. wpp/aggregate.py aggregated every name with its notebook count and notebook list, and derived the year/family of a notebook from its file name (the part before the first hyphen, trailing digits stripped).
2. wpp/resolve.wls evaluated, for every ResourceFunction name, TimeConstrained[ResourceObject[name], 60] and recorded ResourceType, Description, ContributedBy, ReleaseDate, UUID, DocumentationLink, RepositoryLocation and Version (results cached in rf_resolved.json).
3. wpp/resolve_uuid.wls evaluated TimeConstrained[ResourceObject[uuid], 60] for every embedded UUID, and a follow-up script evaluated ResourceObject[CloudObject[documentationLink]] for a sample of the private documentation pages (they resolve to a Function resource with the embedded UUID but the Description property fails).
4. wpp/doclinks.sh fetched every embedded DocumentationLink with curl (-s, -L) and recorded the HTTP status, final URL and page title (all return 200 with the title "Name | Wolfram Resource Object" and no sign-in redirect).
5. Fetched https://resources.wolframcloud.com/FunctionRepository/autocomplete/allnames.json (3320 names) and flagged every name that resolves in the kernel but is absent from the list as legacy or delisted.
6. wpp/pacletsyms.wls loaded the installed paclets SetReplace 0.3.196, WolframInstitute/Hypergraph 1.2.3, Wolfram/Multicomputation 0.1.9, WolframInstitute/HypergraphRewriteEngine 0.0.1, Wolfram/Lambda 1.2.4, WolframInstitute/TuringMachine 1.2.0, Wolfram/Metamathematics 1.0.2, Wolfram/Lazy 1.0.5, Wolfram/QuantumFramework 2.1.1, WolframInstitute/Infrageometry 1.0.14, WolframInstitute/CellularAutomaton 1.0.4, WolframInstitute/NetworkSystem 1.1.5, WolframInstitute/PiMachine 1.0.3 and WolframInstitute/SyntheticInfrageometry 0.12.36 (Needs on each Kernel extension context), exported the names in each context and their usage messages; wpp/paclet_usage.py read the Usage cell of each ReferencePages/Symbols notebook in the installed paclets to obtain usage text for the paclets that define no usage messages. PacletFindRemote returns nothing for the Paclet Repository paclets (it finds only SetReplace 0.3.196); ResourceObject["Publisher/Name"] returns their Paclet resource: WolframInstitute/Hypergraph 1.2.3 "Hypergraph tools", Wolfram/Multicomputation 0.1.8 "Various functions for multicomputation", Wolfram/Lambda 1.2.4 "Tools for the lambda calculus", WolframInstitute/TuringMachine 1.2.0 "Tools for exploring and analyzing Turing machines", Wolfram/Lazy 1.0.5 "Lazy computation", Wolfram/QuantumFramework 2.1.1 "Perform analytic and numeric quantum computations", WolframInstitute/NetworkSystem 1.1.5 "Network Systems", WolframInstitute/PiMachine 1.0.3 "Universal Reversible Machine"; ResourceObject fails for WolframInstitute/HypergraphRewriteEngine, Wolfram/Metamathematics, SetReplace, WolframInstitute/CellularAutomaton and WolframInstitute/Infrageometry.
7. Paclet Repository reference pages (for example https://resources.wolframcloud.com/PacletRepository/resources/WolframInstitute/Hypergraph/ref/Hypergraph.html) return 200 but are rendered client-side, so the usage text was taken from the installed paclet notebooks instead.

### Step 6: verification

wpp/verify.py re-downloaded five random notebooks with fresh curl calls, mined them again and compared the attributed ResourceFunction names and contexts; and fetched the Function Repository page of five random Table 1 rows to confirm the kernel description appears on the page. Results are in the Verification section.

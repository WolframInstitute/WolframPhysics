# Cloud resource functions deployed in the nikm Wolfram Cloud account

Research report for the WolframInstitute/WolframPhysics paclet guide page. Source swept: the resources deployed under https://www.wolframcloud.com/obj/nikm/DeployedResources/ in the Wolfram Cloud account of Nikolay Murzin (nikm, Wolfram Institute), which the Wolfram/Multicomputation paclet, Wolfram Community posts and Stephen Wolfram's writings call as private or semi-public resources. Every row below was seen in a WL 15.0 kernel evaluation (cloud-connected as nikm) or on a fetched page; the Method section says which. Sweep date: 2026-09-17.

Summary of what was found:

- The Function folder holds 61 deployed function resources. 59 are world-readable (Permissions All -> Read or All -> Read, Execute), 2 are owner-only (SchematicEye, SchematicEyePlot3D). 31 of the 61 have a public Wolfram Function Repository (WFR) twin of exactly the same name, ImportSafeTensors has its twin under the different spelling ImportSafetensors, and 29 exist only in the cloud account.
- 29 of the 61 are relevant to the Wolfram Physics Project or its ruliology tools (multiway systems, token-event graphs, causal graphs, foliations, metamathematics, Turing machines, tag systems, combinators, cellular automata). The physics-relevant cloud-only functions are AccumulativeTokenEventGraph, MultiEvaluate, Coordinatize, GraphProduct, UnfailingKnuthBendixCompletion, TreeSearch, OneSidedTuringMachineFunction, CombinatorBooleanFormula, BusyBoxes and SerratedBricksArrayPlot.
- Cloud-deployed resources carry Version None; the cloud copies are pre-submission snapshots, and in 25 of the 32 twinned cases the WFR release is newer than the cloud LastModified date (3 same day, 4 cloud newer: MultiwaySystem, DiscreteHypersurfaceDecomposition, EinsteinSummation, NonNegativeMatrixFactorization are redeployed copies of functions by other authors).
- The account also holds 7 Paclet folders (Wolfram/..., WolframInstitute/..., ChristopherWolfram/OpenAILink, Arrays.paclet, plus empty PAdic, Wolfram-QuantumFramework and WolframParser folders), 5 Data resources, 3 Example, 1 ComputationalEssay, 1 Demonstration, 1 FunctionResource and 2 Prompt resources. They are listed in short tables at the end; the paclet symbol lists are in docs/research/wolfram-institute.md and are not repeated here.

## Method

All kernel work ran in WL 15.0 through wolframscript -file on scratch files under the session scratchpad, with each cloud call inside Quiet and TimeConstrained and a progress Print per entry. The kernel was cloud-connected as nikm@wolfram.com (checked with {CloudConnected, WolframID, CloudUserID, VersionNumber} at the start of the first script, output {True, nikm@wolfram.com, nikm@wolfram.com, 15.}).

Kernel evaluations (scratch files nikm_list.wls, nikm_list2.wls, nikm_index.wls, nikm_probe.wls, wp_probe.wls, wp_probe2.wls, nikm_wfr.wls, nikm_verify.wls, dhd_list.wls):

1. CloudObjects[base <> d] for d in "", "Function/", "Paclet/", "Data/", then "ComputationalEssay/", "Demonstration/", "Example/", "FunctionResource/", "Prompt/", "deployedresourcesdata/", "Paclet/Wolfram/", "Paclet/WolframInstitute/", "Paclet/ChristopherWolfram/", "Paclet/PAdic/", "Paclet/Wolfram-QuantumFramework/", "Paclet/WolframParser/", every "Paclet/Wolfram/<name>/" and "Paclet/WolframInstitute/<name>/" folder, "Paclet/ChristopherWolfram/OpenAILink/", "Paclet/Arrays.paclet/", and "Function/DiscreteHypersurfaceDecomposition/", "Function/NestGraphTagged/", "Function/MultiEvaluate/", "Function/TreeSearch/", with base = https://www.wolframcloud.com/obj/nikm/DeployedResources/ . CloudObjectInformation on index.html and deployedresourcesdata; CloudGet and Import[..., "Text"] of deployedresourcesdata/resources.json (it is a Delayed expression that regenerates the account's public resource index, not a static file).
2. For each of the 61 Function entries: CloudObjectInformation[CloudObject[url]] (properties Permissions, Created, LastModified, MIMEType, FileByteCount, UUID, Active), then ResourceObject[CloudObject[url]] with the properties Name, UUID, Version, ResourceType, Description, Details, Keywords, Categories, ContributorInformation, DocumentationLink, FunctionLocation, ReleaseDate, RepositoryLocation, ResourceLocations, RelatedSymbols, SeeAlso, ExternalLinks, SourceMetadata, Usage, FunctionInformation, Properties; then ResourceFunction[ro] inside TimeConstrained[..., 90] and Options[rf]. "FunctionInformation" is not a property of these objects (it returned Failed for every entry); "Usage" is, and was used. Details, ReleaseDate, RepositoryLocation, RelatedSymbols, SeeAlso are not known properties of cloud-deployed resources (Failed everywhere).
3. For each of the 61 names: ResourceObject[name] by name with the properties Name, UUID, Version, ReleaseDate, RepositoryLocation, ResourceLocations, Description, ContributorInformation, DocumentationLink (to learn whether a public WFR function of the same name exists). Because ResourceObject[name] answers from the local resource cache when a copy is cached, the WFR version and latest release date in the tables come from the fetched WFR page (Version History block) and the kernel value is noted only where it differs.
4. ResourceObject[CloudObject[url]] and CloudObjectInformation on 18 resources in other accounts (wolframphysics, sw-writings0, richardassar, sw-blog), listed in the section "Other accounts (permission probes only)". No directory listing was attempted on those accounts.
5. Verification pass in a fresh kernel (nikm_verify.wls): CloudObjectInformation and ResourceObject (Name, UUID, Version, ResourceType, Description, ContributorInformation, DocumentationLink) on all 61 Function entries again, and ResourceObject on the 36 Paclet, Data, Example, Demonstration, ComputationalEssay, FunctionResource and Prompt entries. A third kernel (dhd_list.wls) retried NestGraphTagged with TimeConstrained 300 after it timed out twice at 90 seconds, and read ReverseAddSequence.

Web fetches (curl, unauthenticated):

- https://resources.wolframcloud.com/FunctionRepository/resources/<Name>/ for all 61 names, saved and parsed for title, Contributed by, description, first usage and the Version History block. A real WFR page has the title "<Name> | Wolfram Function Repository"; a name with no WFR entry redirects to https://account.wolfram.com/login/oauth2/sign-in with the title "Wolfram Account Sign-In" (HTTP 200 after redirect, 4493 bytes). The ImportSafeTensors request (capital T) also redirects to sign-in; the WFR entry exists only under the spelling ImportSafetensors. (An earlier draft of this report said the capital-T request landed on the ImportSafetensors page; that was an artifact of saving both fetched pages under names that differ only in case on a case-insensitive file system, and was corrected in the verification pass.)
- Every DocumentationLink returned by the kernel, that is https://www.wolframcloud.com/obj/nikm/DeployedResources/Function/<Name> for all 61 names, saved and parsed for title, description, usage lines, Details and Options text, Contributed by and example section headings. A public page has the title "<Name> | Wolfram Resource Object". Results: 58 pages with that title and a body of 47 KB to 3.2 MB; SchematicEye and SchematicEyePlot3D redirect to the Wolfram Account sign-in page (owner-only objects); DiscreteHypersurfaceDecomposition returns HTTP 200 with content-length 0 (its deployed index.html is a 0-byte file, confirmed with CloudObjects on that folder: DefinitionNotebook.nb 21.4 MB, ExampleNotebook.nb 20.7 MB, ResourceObject.wl 3392 bytes, index.html 0 bytes).
- WebFetch on five cloud pages: MultiEvaluate, TreeSearch, UnfailingKnuthBendixCompletion, AccumulativeTokenEventGraph, CombinatorBooleanFormula (all returned the "Wolfram Resource Object" page with the description and usage quoted in the tables); WebFetch on Coordinatize failed with a socket hang up and on GraphProduct and DiscreteHypersurfaceDecomposition with a timeout or empty body, so those three rest on curl and the kernel.

Cross-reference: grep -w of each of the 61 names over docs/research/*.md (the ten earlier reports), and reading of the MultiEvaluate, Coordinatize, TreeSearch, OneSidedTuringMachineFunction, SubexpressionPositions and nikm lines in stephen-wolfram-writings.md, github-and-source-code.md, wolfram-community.md and wolfram-institute.md.

Not used: ResourceSearch, WolframLanguageContext, WebSearch (the source is a directory listing, so no search was needed). The kagi MCP server was down.

## Findings

Column notes for the function tables. Source is always "cloud resource function, nikm account" (ResourceType "Function", Version None). URL is the DocumentationLink, which is the same as the deployed object URL. Description is the value of ResourceObject[...]["Description"] as returned by the kernel; "placeholder description" means the definition-notebook template text "One-line description explaining the function's basic purpose" was returned. Permissions and dates are CloudObjectInformation Permissions, Created and LastModified (year-month-day). WFR twin gives the public Function Repository entry of the same name with its version and latest version date from the WFR page, and says which of the two is newer by date. Status "seen" means ResourceObject[CloudObject[url]] resolved in the kernel and the page was fetched; "unconfirmed" means the cloud object exists (CloudObjectInformation resolved) but ResourceObject failed, so nothing beyond the name, permissions and dates is verified.

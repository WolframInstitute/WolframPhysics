# Wolfram Function Repository by keyword: functions relevant to the Wolfram Physics Project

Research report for the WolframInstitute/WolframPhysics paclet guide. Sweep date: 2026-09-16. Finder scope: the Wolfram Function Repository (WFR) searched by keyword, by category page, by kernel ResourceSearch and by WolframLanguageContext. Every function listed below was seen by this finder on its own WFR page, in a WFR search result or in a kernel evaluation; the Status column says which, and anything not confirmed on its own page or in the kernel is marked unconfirmed.

Summary of counts: the WFR category "Wolfram Physics Project" lists 221 functions; keyword searches found 78 further relevant functions outside that category; 299 functions in total are recorded, of which 16 carry an obsolete notice on their page.

## Method

### Site search by keyword

The WFR search page https://resources.wolframcloud.com/FunctionRepository/search?i=hypergraph is rendered client-side. Its HTML (fetched with curl) loads results from a JSON endpoint, so the sweep called that endpoint directly for every term:

    https://www.wolframcloud.com/obj/resourcesystem/api/1.0/SearchResources?ResourceTypes=Function&Format=json&Count=1000&WebFiltering=True&Query=<term>

Each response carries Name, UUID, Description, ReleaseDate, Score and FilterCategories per resource. Multi-word queries are OR-ed by the endpoint (they return up to 1000 hits, ranked by Score), so for those the top-scored hits were reviewed and a relevance filter on name and description was applied; single-word queries were reviewed in full. Scripts: sweep.py (first pass, 118 terms) and kw_sweep3.py (second pass, six parallel workers) in the session scratchpad; a serial second pass (kw_sweep2.py) was abandoned after 14 terms because the 1000-hit responses made it too slow, and its partial results were merged. ### Category pages

The WFR home page https://resources.wolframcloud.com/FunctionRepository/ lists category pages. The category page https://resources.wolframcloud.com/FunctionRepository/category/wolfram-physics-project is also client-rendered; its data-url attribute points at

    https://www.wolframcloud.com/obj/resourcesystem/published/FunctionRepository/category/wolfram-physics-project-data.json

which was fetched in full (221 resources). The same endpoint pattern was fetched for graphs-networks (377), higher-mathematical-computation (979), symbolic-numeric-computation (1108), scientific-and-medical-data-computation (288), core-language-structure (319), geometry (429), strings-text (260), visualization-graphics (617) and just-for-fun (259), and their names and descriptions were scanned with the same relevance filter. There is no separate "Discrete Mathematics / Computational Systems" top-level category on the WFR; the closest are the "Wolfram Physics Project" category and the "Discrete Mathematics" and "Computational Systems" subcategory labels that appear inside FilterCategories of individual resources.

### Full name list

The category page markup also names https://resources.wolframcloud.com/FunctionRepository/autocomplete/allnames.json, the autocomplete list of every published function name (3320 names on the sweep date). It was fetched and pattern-matched on physics-related stems (Hypergraph, WolframModel, Multiway, Causal, Branchial, Combinator, Turing, Automaton, TagSystem, Quantum, Curvature, Dimension, Tiling, Proof, Axiom, Rule, Nest, Trace, Tensor, Einstein, Ricci and about a hundred more) as a final completeness check on the keyword sweep.

### Resource pages

Every candidate's page https://resources.wolframcloud.com/FunctionRepository/resources/<Name>/ was fetched with urllib (script kw_scrape.py) and parsed for the one-line description, the "Contributed by:" line, the Related Resources list, the version history and any "This resource function is obsolete" notice. Related Resources links were followed to find further candidates (this is how the obsolete QuantumDiscreteState family, RandomCA and StringOverlaps were found).

### Kernel evaluations (WL 15.0, wolframscript -file)

- kw_rsearch_probe.wls: ResourceSearch["hypergraph"] returned a Dataset of 31 rows (3 paclets, 28 functions), confirming the call form.
- kw_rsearch2.wls: ResourceSearch[t] wrapped in TimeConstrained[..., 240] for t in hypergraph, multiway, causal graph, combinator, cellular automaton, Wolfram model, all in one kernel. Only the first term completed; after the first TimeConstrained abort every later call in that kernel also timed out, so the run was abandoned.
- kw_rsearch3.wls (multiway, causal graph; 900 s limit) and kw_rs_<term>.wls (combinator, cellular automaton, Wolfram model, hypergraph; 600 s limit, one kernel process per term): ResourceSearch[t] with Normal and Lookup of Name, ResourceType and Description, exported to JSON. Run one term per fresh kernel, each call returned in well under a minute; the earlier timeouts were an artifact of reusing a kernel after an abort.
- kw_meta.wls: for each of the 299 candidates, ResourceObject[name] with the properties "Description", "Keywords", "ContributorInformation" (ContributedBy), "Categories" and "Version", written to kw_meta.jsonl. All succeeded except DynamicCellularAutomaton (ResourceObject failed in the kernel; its web page exists). SuzukiTrotterProduct is the reverse case: its web page redirects to a Wolfram sign-in page, but ResourceObject succeeded in the cloud-connected kernel.

### WolframLanguageContext queries

Three natural-language queries were sent to the Wolfram MCP WolframLanguageContext tool: (1) WFR functions for hypergraph rewriting, Wolfram models, multiway systems, causal and branchial graphs, token-event graphs, causal invariance and Knuth-Bendix completion; (2) WFR functions for dimension and curvature of graphs, spacetime sprinkling, embedding hypergraphs into manifolds, quantum mechanics, ZX-calculus and entanglement entropy; (3) WFR ruliology functions (cellular automata variants, tag systems, register machines, Turing machine enumeration, adaptive evolution, aggregation systems, rule enumeration). The functions surfaced are listed in the fourth findings table.

## Findings

Column conventions: Source is WFR for a Function Repository function; Topics gives the topic group used in this report followed by the resource's own Keywords from the kernel (when it has any) and any obsolete notice from its page; Contributor is the "Contributed by" line from the page (falling back to ContributorInformation from the kernel); Status is seen when the function's own page was fetched or ResourceObject succeeded in the kernel, and unconfirmed otherwise (including rows that appeared only in a search result or a RAG snippet). The Verification section at the end records a second pass (2026-09-16) that resolved every row in the kernel or on its page, so no row is left unconfirmed; for paclet symbols the evidence there is Names in the paclet context, and for paclets and data resources it is PacletFindRemote or ResourceObject.

## Gaps

- ResourceSearch was run for six terms only (hypergraph, multiway, causal graph, combinator, cellular automaton, Wolfram model), one fresh kernel per term, because a second ResourceSearch call in the same kernel hung every time it was tried. It returns at most 50 rows per query, so it is a cross-check rather than an exhaustive source; the web search endpoint covers the same index with Count=1000.
- Multi-word site queries are OR-ed, so their long tails (up to 1000 hits) were reviewed only through score ranking and a name/description relevance filter, not exhaustively by eye.
- Keywords come only from the kernel ResourceObject metadata; 28 functions have an empty Keywords field there and the web pages do not show keywords, so those rows have topic labels only.
- The WFR web pages do not expose the full "Categories" subcategory labels (such as Discrete Mathematics or Computational Systems) except through FilterCategories in the search JSON; no dedicated category page exists for those labels, so the category-page method was applied to the Wolfram Physics Project category plus nine adjacent categories instead.
- The kagi MCP server was unavailable this session; no general web search engine was used, only the WFR endpoints, the kernel and WolframLanguageContext.
- Paclet Repository, Community posts, GitHub and Stephen Wolfram's writings are covered by other finders and were not swept here; paclets that ResourceSearch or WolframLanguageContext happened to return are noted but not investigated.

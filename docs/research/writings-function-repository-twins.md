# Writings functions with Function Repository twins, and repository functions the writings use

Research report for the WolframInstitute/WolframPhysics guide pages. Source swept: the functions that Stephen Wolfram's writings, the four Physics Project bulletins, the technical introduction and the wolframphysics.org program files define inline (the guides tag them (Writings) or (wolframphysics.org), or list them untagged under a per-source subsection of that name), checked against the Wolfram Function Repository for a published counterpart under the same or a near name; and the public Function Repository functions those writings call that no guide page lists. Sweep date: 2026-09-21. Kernel: WL 15.0 via wolframscript, not cloud connected, so ResourceObject resolves a public Function Repository resource anonymously and fails on anything that needs a login.

Verdict column: "same" means the published function is the writings function, published under that name (the writings file is a copy of it, or the repository page credits Stephen Wolfram for the original) or the same computation on the same arguments; "equivalent" means the published function gives the writings function's result through a property, an option value or a different rendering; "related" means a published function covers the same ground with a different contract, recorded so the reader knows it was weighed and not treated as a twin. Pages are the guide pages that list the writings function, from a grep of docs/en/Guides on the sweep date; the last column says whether the published function is already on those pages.

## Method

Every step below was actually run; scratch files live under the session scratchpad directory twins/.

1. Writings-defined names. parse_reports.py read every table row of docs/research/cloud-program-files.md, stephen-wolfram-writings.md, stephen-wolfram-writings-pre-2020.md and wolframphysics-archives-notebooks.md (2425 rows) and kept the rows whose source is a program file, a private cloud resource, a post-local definition or a recurring notebook helper: 906 distinct names. guide_names.py read every `- ` bullet of the 35 guide pages and kept each link tagged (Writings), (wolframphysics.org), (Archives) or (Cloud: wolframphysics), and each untagged link under a `### Writings` or `### wolframphysics.org` heading: 150 names on 19 pages, all of them already among the 906. Names beginning with a dollar sign and single-letter names were dropped, leaving 877 to check.
2. Exact-name probe. probe_batch.wls evaluated, for each of the 877 names, Quiet@TimeConstrained[Replace[ResourceObject[name], {r_ResourceObject :> {r["ResourceType"], r["Description"]}, _ -> Null}], 30] in batches of 40 with a progress print, as four parallel wolframscript -file workers: 36 names resolve to a published Function resource (listed in the tables below), 841 fail, none timed out. A lowercase writings name (hypergraphToGraph, ricciScalar) cannot resolve this way, so the near-name pass covers it.
3. Near-name pass. The repository's autocomplete list https://resources.wolframcloud.com/FunctionRepository/autocomplete/allnames.json (3320 names, fetched 2026-09-21) was matched against the 877 names by exact name, substring and CamelCase word overlap after expanding the writings' abbreviations (TS, CT, TM, MW, CA, WM, HG, SK, FSM, NDTM, GCSS, AON, STG, DAG), then by hand through keyword greps of the list (tableau, poset, sort, foliation, signature, bracket, traversal, multispace, tag system, combinator, Turing, token-event, causal, hypergraph, standard order, aggregation, geodesic, curvature and so on). The repository search page https://resources.wolframcloud.com/FunctionRepository/search?i=... renders only the site shell (its results load by script), so it contributed nothing. desc_batch.wls then fetched ResourceType, Description and ContributorInformation for the 309 candidate published names (305 resolve; ArrayTrim, DynamicCellularAutomaton, FindPositions and RhumbLineDistanceList do not resolve by name, as function-repository-by-contributor.md already records for DynamicCellularAutomaton).
4. Equivalence judgement. For every candidate pair whose descriptions were close, the published function's page was read with WebFetch (usage forms, arguments, options and properties, contributor): FindBooleanAlternative, TableauToPoset, PosetToTableau, DepthLeafCountSort, WolframModelSignatureForm, CombinatorBracketsPlot, TraversalOrderSelect, MultispacePlot3D, GraphReconstructedSurface, StandardOrderIndex, TuringMachineCausalGraph, FindFiniteModels, FindEquationalPath, TagSystemEvolveList, TagSystemConvert, TagSystem, CyclicTagSystem, MultiwayTuringMachine, MultiwayCombinator, CombinatorConvert, CombinatorEvolutionGraph, TokenEventGraph, HypergraphPlot and WolframModelEvolutionObject. The writings side was taken from the call signatures and paraphrases in cloud-program-files.md and the descriptions in the other three reports.
5. Resource functions the writings call. The rows of the four reports whose source is WFR give 248 distinct names called with ResourceFunction in the posts, bulletins, technical introduction and archive notebooks. Each was grepped over docs/en/Guides as a code-span link or a /resources/Name/ address: 150 are on some page, 98 on none. The 98 were sorted by subject with the usage recorded in the reports; the ones with a guide subject are proposed below, the rest are listed so the exclusion is visible.
6. URL check. Every published address in the tables below was fetched with curl -L on 2026-09-21: all return HTTP 200 at the same address, and each page title is the function name followed by "Wolfram Function Repository" (a repository address for a name that does not exist redirects to the search page, and none did). Where a published function is said to be on a guide page, that is a grep of docs/en/Guides on the sweep date.

Notes on the judgements:

- FindBooleanAlternative is credited to Stephen Wolfram and Nikolay Murzin and takes an operator set and an optional size, the arguments the metamathematics essay uses; function-repository-by-keyword.md had set it aside as not physics-related, and the guide already carries it under its Function Repository subsection, so the pair is a labelling question, not a coverage gap.
- TableauToPoset and PosetToTableau (Ed Pegg Jr) take and return the same list-of-coordinates poset the technical introduction's YoungTableauToPoset.wl uses, and their pages link the same tableau family that file ports from Combinatorica (StandardYoungTableaux, RandomYoungTableau, NumberOfTableaux, TableauQ, TransposeTableau, PermutationToTableaux, TableauxToPermutation), so the whole file has a published counterpart.
- TraversalOrderSelect takes the scheme {"Leftmost" or "Rightmost", "Outermost" or "Innermost", n} that EvaluationOrderSort takes, and CombinatorMatches sorts its matches by the same scheme.
- CombinatorEvolutionGraph's three properties, HaltedStatesGraph, PathHighlight and CausalGraph, with the MinimalHaltedStatesGraph and EvaluationScheme options, are the three combinator graph helpers of the combinators bulletin; MultiwayCombinator gives the same states graph without the halting decoration.
- CombinatorConvert's String, Nested, List and Application formats cover CombinatorFromString, FunctionToApplication and NestedFunctionsToLists, with one difference: its string form is the left-associative "S(KS)I" convention, where the bulletin parses "s[k][s]".
- TagSystem (Stephen Wolfram) has exactly the {n, rule}, init, t signature of TSEvolveList; TagSystemEvolveList adds the "Post" rules by name, the compressed {phase, digits} state that TagSystemConvert produces, and evolution until halting, which is the halting side of FindPostTagFate. CyclicTagSystem (Stephen Wolfram) and CyclicTagSystemEvolveList both give the list of states of CTEvolveList.
- MultispacePlot3D is the general multispace embedding on timelike, spacelike and branchlike axes that TMAppliesMultispace draws for one Turing machine; applied to MultiwayTuringMachine it is the same picture.
- FindEquationalPath produces what FindTokenEventProof draws through the token-event graph, a proof as a path of single replacements, but derives it from FindEquationalProof by cut elimination rather than searching the graph; it is on both metamathematics pages already.
- WolframModelSignatureForm prints a signature as 22->32 where RuleSignatureForm prints subscripted counts; the technical introduction's histogram and rule enumeration figures use the subscripted form, so the guide may keep the writings entry and cite the published one as the alternative.

## Gaps

- The Wolfram/Metamathematics paclet (sw1sh/WolframMetamathematics), not the Function Repository, is where the writings' two-way rule, token-event proof and pattern canonicalization functions were published (TwoWayRuleMultiReplace, TwoWayMultiReplace and the rest); the guides already list those paclet symbols beside the writings entries. A paclet-side twin table would be the natural sequel to this report, and the WolframInstitute/TuringMachine paclet (MultiwayTuringMachinePlot, OneSidedTuringMachinePlot) is the other place where writings plotting helpers reappear.
- Equivalence was judged from repository pages and the reports' call signatures, not by running the two implementations side by side: the writings program files are cloud objects that the kernel cannot load without a login on this machine, and the archive notebooks' helper definitions were not re-evaluated. The verdict column says which judgements rest on a description alone (CanonRule, GroupToMW, ToMultiwaySystem).
- The 371 writings cloud resources of stephen-wolfram-writings.md section 4 carry no Description, so their near-name matching used the report's inferred one-line descriptions. Names that describe a whole family (the finite state machine game strategies, the aggregation and rule array functions, the tic-tac-toe and Go graphics) were not searched for twins individually; none of them is on a guide page.
- The repository search page loads its results by script, so no site search was run; the exhaustive name list stood in for it, which finds near names but not a published function whose name shares no word with the writings name. The keyword greps (Table 2's third column) are the mitigation, not a proof of absence.
- The archive notebooks report was cut off part way through its download and is unverified, so the "used in" evidence of Table 4 for the archive rows (BuckyballGraph, TorusGraph, SetPartitions, ArrayRotations, ArrayCrop, ReplaceAt, ChromaticNumber) counts notebooks that were read, not all notebooks.
- The Wolfram/QuantumFramework symbols the archive notebooks use (QuantumTensorProduct, QuantumBasis, QuantumPartialTrace, QuantumMeasurementOperator, QuantumDistance, QuantumEntangledQ, QuantumWignerTransform, QuantumWeylTransform, all from the 2020 Shor algorithm notebooks) are paclet symbols, outside this report's Function Repository scope; QuantumDistance, QuantumEntangledQ, QuantumPartialTrace and QuantumMeasurementOperator are on the branchial graphs page, the others are not on any page.
